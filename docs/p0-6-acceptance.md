# P0-6 跨展示機拍照紀錄

舊規劃對話將拍照紀錄列為後續功能；[階段規劃](test-plan.md)只明列到 P0-4。依本次確認，P0-6 採用 Supabase 雲端紀錄，供工作人員跨展示機彙整，開發起點為 main 的 `c5173cb`。

## 使用與範圍

- 一張正式合照成功產生 PNG 後新增一筆。記錄照片 UUID、拍攝幀時間、人數、展示機代號、分享狀態與版本號。場地試拍及合成失敗均不計入。僅按分享才上傳影像；紀錄不含照片、臉部座標、簽名連結。
- 每次成功重拍產生新編號。同一張重試分享或重建連結更新原紀錄；「已產生分享連結」表示該次分享成功，無法據此推算實際下載次數。
- 展示機以該瀏覽器的匿名 Supabase 帳號作為代號。重新整理沿用同一個帳號；清除站台資料或改用其他瀏覽器會有新代號。
- 展開「本機拍照紀錄」查看本機快取與同步狀態。離線時先保留，恢復網路、重新開頁或按「重試同步」可補送。清除瀏覽器資料之前應確認已同步。
- 模擬模式的紀錄獨立保存，只供測試。正式雲端同步使用一般開發模式或正式建置。
- 首版由專案管理員在 Supabase 查看跨機統計。訪客無法讀取總表。彙整人數以人次計，同一人參加兩張會計兩人次。

## Supabase 安裝與查詢

沿用 P0-5 專案、已開啟的匿名登入與公開連線設定。專案管理員在 SQL Editor 執行一次 [photo-records.sql](../supabase/photo-records.sql)。資料表位於私人 schema，展示機只可呼叫寫入函式，函式從登入身分取得展示機代號；重送舊版本不能覆寫較新狀態。

工作人員用 SQL Editor 執行以下唯讀查詢。第一段每列代表一台展示機一天；第二段為全場每日合計。

```sql
select * from booth_reporting.daily_summary
order by local_date desc, booth_id;

select local_date, sum(photos) as photos, sum(participant_visits) as participant_visits,
       sum(shared_photos) as shared_photos, sum(share_failed) as share_failed
from booth_reporting.daily_summary
group by local_date order by local_date desc;
```

## 驗收

| 場景 | 通過條件 |
|---|---|
| 試拍與正式拍攝 | 試拍 0 筆，取消倒數或合成失敗 0 筆；正式合照成功後新增 1 筆，時間與人數取自拍攝幀。 |
| 重拍與分享 | 重拍新增一筆；分享失敗與成功重試各更新同一筆，原本的 PNG 與 QR 下載仍可用。 |
| 離線與重送 | 頁面顯示待同步；網路恢復後更新為已同步。重複或逆序送達不重複計數，也不回退雲端狀態。 |
| 跨機彙整 | 兩台不同瀏覽器各拍一張（2 人、1 人），管理端同日合計 2 張、3 人次，分機各 1 張；跨台北午夜歸入正確日期。 |
| 存取 | 展示機不能讀全場明細、修改其他登入身分的紀錄；管理員可查每日統計。 |
| 回歸 | 停止、重開、下載、產生 QR 維持 P0-5 流程；展場光線與去背畫質沿用「待展場確認」。 |

本機 PostgreSQL 使用兩組測試登入身分驗證資料庫行為。實際 Supabase 安裝與兩台展場機器對帳須另行驗收。

2026-11-10 開發分支驗證：21 項自動測試通過。Chrome 模擬拍攝確認試拍不留紀錄、兩次正式合照各一筆、分享失敗後重試更新原筆，兩組 QR 仍能取回對應 PNG。模擬 Supabase 暫時失敗後重新開頁，確認待同步轉為已同步。本機 PostgreSQL 已驗兩機分組、台北日期、寫入權限、重送與逆序版本。尚未在正式 Supabase 套用本階段 SQL。

### 展場倒數快門

任一人比讚滿 1 秒或按下拍攝按鈕，啟動可取消的 3 秒倒數。倒數期間參觀者可以放下手或移動，系統取快門當下的影像。持續比讚只觸發一次；放下再比可拍下一張。畫面中的其他人不需要比讚。影像會保留分割模型辨識到的所有人物。分享仍需另外按下上傳按鈕。

Chrome 雙人模擬畫面已驗：無人比讚時按鈕拍攝、倒數取消、只有一人比讚時自動拍攝、維持比讚不連拍，兩張合照各記錄 2 人。真人展場體驗待驗。
已安裝舊版資料表的專案請重跑本分支的 photo-records.sql，以允許記錄偵測為 0 或超過 5 張臉的拍攝結果。
