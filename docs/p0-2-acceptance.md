# P0-2 部署與驗收

## 本機驗證

1. 安裝 Node.js 22.13 以上（或 24）與 npm。進入專案目錄，切到 `p0-2-development`。
2. 執行 `npm ci`，再執行 `npm test`。四項測試使用合成方框驗證最大面積、切換延遲與插值、短暫失焦與回中，以及左右眼與鏡像的角度。
3. 執行 `npm run build` 和 `npm run preview`。開啟終端顯示的 localhost 網址並進入 `/ai-character-photo-booth/`。開發模式可改執行 `npm run dev`。
4. 按「開始展示」，允許使用攝影機。首次啟動需載入 WASM 與模型；觀察除錯資訊中的偵測器與角色狀態。若失敗，記下錯誤文字與裝置，停止後再啟動。

## 部署到 GitHub Pages

1. 將開發分支推到 GitHub：`git push -u origin p0-2-development`。推送此分支不會自動發布正式站。
2. 在本機完成下表驗收，再從開發分支建立以 `main` 為目標的 pull request，審查並合併。
3. 在儲存庫 Settings → Pages → Build and deployment 選擇 GitHub Actions。合併至 `main` 會觸發部署；若先前未開啟 Pages，可在 Actions 手動對 `main` 重跑工作流程。
4. 在 Actions 確認 build 與 deploy 兩個工作均成功，再開啟 [正式站](https://slinghuazure-lab.github.io/ai-character-photo-booth/)。確認版本為 P0-2，重新驗收。手機需使用 HTTPS；桌面 localhost 可用。若需回復，回退合併的變更，由同一流程重新部署。

## 實機驗收表

記錄日期、裝置、瀏覽器、通過／失敗、實際解析度與重現步驟。手機直向與展示電腦各測一次。

|操作|通過條件|
|---|---|
|執行 [P0-1 原驗收表](test-plan.md) P01–P15|預覽、啟停、權限、解析度、鏡像、三語、設定保存及全螢幕正常；具雙鏡頭的裝置補測切換，單鏡頭標記不適用|
|無人入鏡，再由一人左右、上下移動|無臉時 V15 小菁鷹播放站立呼吸與左右看動畫；入鏡後臉數為 1、中心更新、眼睛跟隨；切換鏡像，水平方向與預覽一致|
|兩人分居左右，輪流靠近鏡頭|臉數為 2；目標跟隨面積較大的臉；新目標持續約 250 ms 後平滑轉向；短暫超越不應立刻跳轉|
|遮住目標後返回，再離開一秒|短暫漏偵保留目標；連續無臉約 450 ms 後切回待機，眼睛逐漸回中|
|依序按左眼、右眼、拍照動作|以角色自身方向判定；每次僅指定的眼睛眨動。拍照時小菁鷹播放比 YA 動畫，約 6 秒回到站立，視線持續更新|
|查看 Debug，切三種語言，隱藏後重開|攝影機資訊與新增欄位同步；偵測頻率和單次耗時獨立於畫面 FPS；目標欄為平滑後的原始影像正規化座標|
|連續啟停三次，切換可用鏡頭／解析度|停止時攝影機釋放，角色消失且偵測停止；每次重啟可再次追蹤。單鏡頭無法驗證實體鏡頭切換|
|在瀏覽器開發者工具封鎖模型檔後重新開始|偵測器顯示失敗，攝影機與角色仍可使用；解除封鎖，停止再開始後恢復|

拍照按鈕只測試姿勢，不產生影像檔。人臉偵測比較當前方框的位置與面積，不建立身分識別資料。
